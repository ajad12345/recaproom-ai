Introduction to Machine Learning - Lecture 3 (synthetic sample)
Today we will look at the basic ideas behind machine learning. Machine learning is defined as the study of algorithms that improve their performance on a task through experience, instead of being programmed with fixed rules.
The most common setting is supervised learning. In supervised learning we have examples where both the input and the correct output are known. For example, a set of house descriptions together with their sale prices can be used to learn a price predictor.
There are two main kinds of supervised problems. Regression means predicting a number, such as a price or a temperature. Classification means predicting a category, such as whether an email is spam or not spam.
In unsupervised learning there are no correct outputs. The algorithm looks for structure by itself. Clustering is a typical example, where similar data points are grouped together without any labels.
A model is a function with adjustable parameters. Training means finding parameter values that make the predictions close to the known answers. The measure of how wrong the predictions are is called the loss function.
For regression we often use the mean squared error as the loss. It is important to remember that the loss is only a number that guides training. A low loss on the training data does not automatically mean the model is good.
Gradient descent is the most common method to reduce the loss. The idea is simple. We compute the slope of the loss with respect to each parameter and then move the parameters a small step in the opposite direction of the slope.
The size of that step is called the learning rate. If the learning rate is too large, training can overshoot and diverge. If it is too small, training becomes very slow. Choosing it well is a key practical skill.
Overfitting happens when a model learns the noise in the training data instead of the real pattern. An overfitted model has a very low training error but a high error on new data. This is the central problem in machine learning.
Underfitting is the opposite problem. The model is too simple to capture the pattern, so the error is high on both training and new data. A straight line fitted to clearly curved data is an example of underfitting.
To detect overfitting we split the data into a training set and a test set. The model learns from the training set only. The test set is kept hidden and is used once at the end to estimate how the model will behave on new data.
Often we also need a validation set to choose settings such as the learning rate. If we tuned the settings on the test set, the test result would be too optimistic, because the test set would no longer be unseen.
Cross validation is a more careful approach when data is limited. We split the data into k folds, train on k minus one folds and validate on the remaining fold, and repeat this k times. The average score is more reliable than a single split.
Regularization is a way to fight overfitting. It adds a penalty for large parameter values to the loss, which pushes the model towards simpler solutions. L2 regularization penalises the squared size of the weights.
The bias and variance trade-off explains these ideas. A model with high bias makes strong simplifying assumptions and underfits. A model with high variance reacts too much to the particular training sample and overfits. We want a balance between the two.
A decision tree is a model that asks a sequence of yes or no questions about the features. Each question splits the data into smaller groups. Trees are easy to explain, but a deep tree can easily overfit the training data.
Random forests reduce this problem. A random forest trains many trees on random parts of the data and averages their answers. Because the trees make different mistakes, the average is more stable than any single tree.
The k-means algorithm is a basic clustering method. First we choose k, the number of clusters. Then we place k centres, assign every point to the nearest centre, move each centre to the mean of its points, and repeat until nothing changes.
How do we choose k in k-means? There is no perfect rule. One common approach is the elbow method, where we plot the error against k and look for the point where improvement slows down.
Accuracy is the simplest evaluation metric. It is the fraction of correct predictions. But accuracy can be misleading when the classes are imbalanced. If ninety nine percent of emails are not spam, a model that never predicts spam is ninety nine percent accurate and completely useless.
For that reason we also use precision and recall. Precision is the fraction of predicted positives that are really positive. Recall is the fraction of real positives that the model finds. The F1 score combines both into one number.
A confusion matrix shows the counts of true positives, false positives, true negatives and false negatives. It is the best starting point for understanding where a classifier makes mistakes.
Feature scaling is another practical point. When features have very different ranges, gradient descent becomes slow and unstable. Standardising each feature to zero mean and unit variance usually helps.
Data leakage is a serious mistake. It happens when information from the test set influences training, for example when we scale the data using statistics computed on the whole dataset. Always fit the scaling on the training set only.
To summarise, a good machine learning workflow splits the data first, trains a simple baseline, checks for overfitting, tunes settings on validation data, and reports the final result once on the test set.
